# Week 6 RAG plan

## Goal and agreed decisions

Build a functional RAG system over `data/book.txt`, preserving the starter's
existing behavior while adding a book-specific path.

- The canonical source is `data/book.txt`; do not rename or copy it.
- The book corpus contains only Machiavelli's dedication to Lorenzo de' Medici
  and Chapters I–XXVI. Exclude all preceding material, including the contents
  and Marriott's introduction, the Project Gutenberg frame, and all appendices
  after Chapter XXVI.
- Find chapter headings in the body, using the contents only as a consistency
  reference. Fail clearly unless exactly Chapters I–XXVI are found in order.
- Keep the existing `default` and `training-rag` profiles and their CLI behavior
  working. The book is an additional loading path.
- Final answers are natural-language LLM syntheses grounded in retrieved text,
  with citations to chunk IDs. Extracted chunks alone are not a final answer.
- Keep the starter character chunker as a comparison configuration. Book
  chunking must preserve chapter boundaries, use overlap, and avoid splitting
  words when possible. Measure the embedding model's token limit with its
  tokenizer; target at most about 220 tokens per chunk. Offline tests use an
  approximate character check; a separately marked integration check uses the
  actual tokenizer.
- Use a local `all-MiniLM-L6-v2`-class sentence-transformers embedder behind a
  replaceable interface. Use FAISS `IndexFlatIP` with L2-normalized vectors for
  cosine similarity. Persist the index and ID-to-chunk mapping under `.cache/`
  (ignored by git) with a manifest containing the text hash, chunking
  parameters, and model name so stale indexes can be detected.
- Retrieve top-N candidates (initial example N=20), then rerank with FlashRank
  and retain top-k (initial example k=4). Show reranker scores.
- Generate with Gemini through Google's official SDK. Read the API key from
  `GEMINI_API_KEY`; read the configurable model from `GEMINI_MODEL`, defaulting
  to `gemini-3.1-flash-lite`. Never put secrets in source or the repository.
- Validate that every cited chunk ID belongs to the retrieved context. Refuse
  unsupported questions using a calibrated reranker threshold plus prompt
  instructions. Refusal must work without Gemini. If generation is unavailable
  or the key is missing, report a clear generation error, show retrieved
  evidence, and do not fabricate an answer.
- Keep tests offline using fake embedders and fake LLMs. Do not break existing
  tests, CLI behavior, or the `default` and `training-rag` profiles without
  agreement. Pair report and contribution descriptions are written by the
  students, not generated by this project work.
- Target Python 3.12. Do not install new packages before the dependency review
  and user approval.

## Target architecture

1. **Corpus preparation:** load the source file, validate Gutenberg markers,
   select the dedication and Chapters I–XXVI from body headings, and attach
   chapter label/title and part-order metadata.
2. **Chunking:** retain the starter overlap chunker as one comparison option;
   add chapter-aware, word-boundary-aware chunking with measured token limits.
3. **Embeddings:** expose a small embedder interface, with a local
   sentence-transformers implementation and deterministic fakes in tests.
4. **Vector store:** use normalized embeddings and FAISS `IndexFlatIP`; persist
   index, ID mapping, and freshness manifest under `.cache/`.
5. **Retrieval:** request top-N FAISS candidates.
6. **Reranking:** use FlashRank on candidates, return top-k and expose scores.
7. **Generation:** use a Gemini adapter configured through environment
   variables, ground generation in retrieved context, and validate cited IDs.
8. **Refusal and orchestration:** combine calibrated reranker threshold,
   grounded prompt behavior, and a pipeline that can refuse without Gemini.
9. **CLI and evidence:** preserve existing CLI paths; add the book workflow and
   reproducible evidence capture based on actual executions.

## Seven implementation phases

### Phase 1: corpus contract and data model

Add a loader for the canonical source that removes the Gutenberg frame,
excludes contents, translator introduction and material after Chapter XXVI,
and returns the dedication plus 26 chapter documents with chapter label/title
and part-order metadata. Missing or malformed structure must raise a clear
error. Keep the existing corpus profiles intact.

**Done when:** tests prove the selected content, exclusions, all 26 headings,
metadata/order, and clear failures for malformed structure; existing tests
continue to pass. Use only the standard library and pytest.

### Phase 2: chapter-aware chunking and comparison

Keep the starter character chunker available and add a book-aware chunker that
does not cross chapters, overlaps, and prefers word boundaries. Compare the
starter baseline (140 characters, 30 overlap) with a book-sized initial
configuration (about 700–850 characters, 100–150 overlap), then use the real
tokenizer to enforce the approximately 220-token target.

**Done when:** chunk IDs are stable and readable, metadata survives chunking,
chapter boundaries are respected, oversize chunks are detected, and Outcome 1
has a reproducible comparison. Offline tests use an approximate character
guard; the real-tokenizer check is separately marked and not part of offline
tests.

### Phase 3: embedder and persistent FAISS store

Define an embedder interface, add the local model adapter, normalize vectors,
implement FAISS `IndexFlatIP`, and persist the index, ID mapping, and manifest
in `.cache/`. Detect stale indexes from source hash, chunk parameters, and
model name.

**Done when:** offline fake-embedder tests cover vector ordering, mapping,
save/load, and stale-manifest detection without network access or model
downloads.

### Phase 4: retrieval, reranking, and refusal calibration

Retrieve top-N vector candidates, rerank with FlashRank to top-k, expose scores,
and add a small repository-held labeled question set including semantically
near unsupported cases. Choose the refusal threshold from measured scores.

**Done when:** tests cover candidate/rerank ordering, labeled examples record
actual scores and decisions, and threshold tradeoffs are documented rather
than assumed.

### Phase 5: Gemini generation and citation validation

Add a Google SDK adapter configured with `GEMINI_API_KEY` and `GEMINI_MODEL`,
prompt for grounded synthesis and refusal, and validate every citation against
retrieved chunk IDs. Preserve evidence and a clear error state if Gemini is
unavailable or unconfigured; refusal remains independent of Gemini.

**Done when:** offline fake-LLM tests cover grounded synthesis, valid and
invalid citations, refusal, missing key, and generation failure without
network calls or fabricated answers.

### Phase 6: CLI integration and compatibility

Expose the book workflow and its parameters while retaining existing CLI
flags, output expectations, and the `default` and `training-rag` profiles.

**Done when:** the existing test suite and CLI behavior remain functional, and
offline CLI coverage exercises both starter profiles and the book path.

### Phase 7: reproducible evidence and final review

Provide a script that records actual commands and outputs into the agreed
`evidence.md` structure, including chunking comparison, top-k, citations,
refusal calibration, and one supported/unsupported pair. Do not fabricate
outputs. Leave pair report and contribution descriptions to the students.

**Done when:** evidence can be regenerated from actual executions, the full
offline tests pass, and submission evidence includes commands, outputs,
retrieved IDs, scores, and threshold rationale.
